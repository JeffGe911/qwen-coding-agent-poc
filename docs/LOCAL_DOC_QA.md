# 本地文档问答 RAG

## 可以看到什么

本地 bge-m3 把问题转成向量，与 BM25 关键词检索合并排序，从 674 个文本分段中取六段交给 Qwen2.5-Coder 7B。
来源为固定版本的 lowRISC 编码规范、Icarus Verilog 和 Verilator 公开文档；版本、原文件哈希和许可证在
[知识库清单](../knowledge/MANIFEST.json)中。运行时只调用本机模型，没有云端模型回退。

程序校验引用的来源编号和引文原文，并给出文件、章节、行范围及链接。没有有效引用时，回答显示“没找到”。
这验证的是引用出处，不是答案的语义正确性：模型仍可能给出与引文不相符的操作，需要人工核对。

## 不加载模型的演示

在仓库根目录运行：

```bash
python scripts/show_doc_qa.py
```

它只读取已经保存的两道开发题，展示原始问题、模型回答、引用和冻结评分；不会发模型请求、运行 shell 建议或改动 RTL。
完整运行记录见 [报告](../evidence/doc-qa/REPORT.md)。

## 在资源充足的电脑上提问

模型需提前下载到监听 `127.0.0.1:11437` 的 Ollama：`bge-m3` 和 `qwen2.5-coder:7b`。
从仓库根目录运行：

```bash
python scripts/ask_local_docs.py "How do I turn off one Verilator warning for the whole run?" --out out/rag-answer.json
```

入口先做资源检查，先检索并卸载 embedding 模型，再调用 Qwen；结束或异常时卸载本次加载的模型。
为避开本次碰到的加载峰值，交互入口要求开始时至少有 8 GiB 可用内存、10 GiB 可提交余量以及 6500 MiB 空闲显存。
不足时直接退出。不会替你关闭其他应用或修改系统内存设置，也不会静默换模型或改用外部 API。

索引已随仓库保存，无需重建。更换知识源时先更新来源清单，再运行 `python -m doc_qa build`。
Python 模块可以安装，但上述命令仍需从完整仓库运行，因为文档、索引和证据不随 wheel 安装。

这两题只作端到端运行示例。不能用它们报告整体准确率。恢复评测时保留这次记录，使用新合同版本并重新记录流程放行条件。
评分中的 `correct` 是答案包含预设关键词，`supported` 是引用分段与标注行范围重叠，都不能代替逐条语义审核。
