指标口径与假设（未经业务确认）

  1. A1 记录口径：测试记录通过率 = PASS 行数 / (PASS + FAIL 行数)，基于去重后的全部行（含重测行）；SKIP 和缺状态行不进分母，单独计数。
  2. A2 最终结果：同一 运行+芯片+项目 取重测轮次最大的那一行；若该轮次存在内容冲突的多行，则判为 INVALID。首测结果取轮次 0。
  3. A3 判定依据：使用测试机记录的状态（status）。状态与上下限不一致的行在质量检查中列出，但不改写状态。
  4. A4 芯片通过：items.json 中每个必测项目在该运行中都有最终 PASS。任一必测项目最终 FAIL → 芯片 FAIL；否则若缺行、SKIP、缺状态或 INVALID → 芯片 INCOMPLETE。
  5. A5 良率给出两个分母：良率(全部) = PASS 芯片 / 全部芯片（INCOMPLETE 算作未通过）；良率(仅完整) = PASS / (PASS + FAIL)。没有给定公司口径，不自行选定其中一个为“官方良率”。
  6. A6 不同运行分开统计。R2 对 LOT-A02 的复测不与 R1 合并成一个良率，而是用运行对比展示变化。
  7. A7 上下限以每行自带的上下限为准（测试机就是这样判定的）；不同文件上下限不一致时在质量检查中报出，跨批次比较时需注意。
  8. A8 分布与趋势只用首测（轮次 0）、数值有效、未被判为不可信或冲突的值，避免重测样本偏向边缘芯片。
  9. A9 异常集中判定（启发式，不是统计检验）：某批次/晶圆在某项目上最终 FAIL 芯片数 >= 5，且失败率 >= 其他所有批次/晶圆合计失败率的 2 倍。
  10. A10 相关不等于因果：报告中的差异只描述数据，不推断芯片失效根因。

SQL 交叉核对

记录通过率（按运行 × 批次）SQL 与 Python 一致：True；各项目最终 FAIL 芯片数一致：True。

SQL
SELECT run_id, lot_id,
       SUM(status = 'PASS') AS pass_rows,
       SUM(status = 'FAIL') AS fail_rows,
       ROUND(1.0 * SUM(status = 'PASS') / NULLIF(SUM(status IN ('PASS', 'FAIL')), 0), 4) AS record_pass_rate
FROM m GROUP BY run_id, lot_id ORDER BY run_id, lot_id

WITH top AS (
  SELECT run_id, chip_key, test_item, MAX(retest) AS r FROM m GROUP BY run_id, chip_key, test_item
), chosen AS (
  SELECT m.run_id, m.chip_key, m.test_item, COUNT(*) AS n, MAX(m.conflict) AS conflict, MAX(m.status) AS status
  FROM m JOIN top ON m.run_id = top.run_id AND m.chip_key = top.chip_key AND m.test_item = top.test_item AND m.retest = top.r
  GROUP BY m.run_id, m.chip_key, m.test_item
)
SELECT test_item, SUM(n = 1 AND conflict = 0 AND status = 'FAIL') AS final_fail_chips
FROM chosen GROUP BY test_item ORDER BY final_fail_chips DESC, test_item
